================================================================================

Everything is in index.html. One file: CSS in one <style> block, HTML in the
middle, JS in one <script> block at the end.

Line numbers below were correct when this was written. They drift as you add
text. If a number looks wrong, search for the quoted marker instead — those
don't move.

Open index.html and press Ctrl+G in VS Code to jump to a line.

5. CHANGING COLOURS
--------------------------------------------------------------------------------

Line 37, the :root block. Never anywhere else.

  --accent            royal blue    (links, metadata, icons at rest)
  --accent-2          turquoise     (gradients, water motif)
  --accent-warm       orange        (flames, bars — GRAPHICS ONLY)
  --accent-warm-ink   dark orange   (orange that has to be READ)
  --paper / --paper-2 backgrounds
  --ink / --ink-2 / --ink-3 / --ink-body   text

>>> Two oranges on purpose. The bright one fails contrast for text. If a person
    has to read it, use --accent-warm-ink.

>>> If you change --accent or --accent-warm, also change them in 404.html
    (its :root is a copy) and in the favicon data-URI at the top of index.html.

7. ADDING IMAGES
--------------------------------------------------------------------------------

STEP 1 — put the files in images/ with lowercase-hyphen names:
    hero.jpg, jpl-1.jpg, jpl-2.jpg, helios-1.jpg, polana-1.jpg, strip-1.jpg ...

    NEVER "HELIOS 1.JPG". Your Mac doesn't care about case; the server does.
    A wrong-case name works locally and 404s on the live site.

STEP 2 — resize BEFORE committing. Run this in the repo folder:

    mogrify -resize 1600x1600\> -quality 82 images/*.jpg

    (Install once with:  sudo apt install imagemagick)

    Check nothing is over ~400KB:

    find images -size +400k -ls

    Git keeps every version of every binary forever. One oversized image
    committed once is permanent weight you can't remove.

STEP 3 — swap each placeholder. Find lines like:

    <span class="label">images/jpl-1.jpg</span>

    Replace the SPAN (keep the wrapper div, it holds the aspect ratio) with:

    <img src="images/jpl-1.jpg" alt="Describe what's in the photo"
         loading="lazy" decoding="async" width="1600" height="1067">

    - loading="lazy" on EVERYTHING except the hero photo and the first
      Highlights card. Those two are on screen immediately; deferring them
      makes them appear later, not sooner.
    - width/height are the file's real pixel size. They stop the page jumping
      around as images load. Get them with:  identify images/jpl-1.jpg
    - alt: if a caption right next to it already says the same thing, use
      alt="". If the photo IS the information, describe it.

STEP 4 — the social preview card. Make a 1200x630 image, save as
    images/og-card.jpg. It's already referenced at the top of index.html.

8. ANALYTICS
--------------------------------------------------------------------------------

At the very bottom of index.html, just before </body>.

To turn it on:
  1. Sign up free at goatcounter.com, pick a code (e.g. "jjcader")
  2. Replace YOURCODE in the script tag with it
  3. Your stats live at jjcader.goatcounter.com

You get: visit counts, which pages, referrers, country, time of day.
You do NOT get: who. No analytics tool can tell you that. The only place
you learn someone's identity is the contact form.

No cookie banner needed — GoatCounter stores no personal data and honours
Do Not Track. (Google Analytics would require a banner. Don't.)

To count clicks on a specific link, add to that <a> tag:
    data-goatcounter-click="cv-download"

9. WORKFLOW
--------------------------------------------------------------------------------

    git pull                  # start of every session
    ...edit...
    git status                # check what changed
    git add .
    git commit -m "what you did"
    git push                  # live in about a minute

Preview locally: right-click index.html -> Open with Live Server.
Never commit just to see a change — the file opens in a browser directly.

To go back to an earlier version:
    git tag                   # list the saved checkpoints
    git checkout v16-404-and-type   # look at one
    git checkout main         # come back


--------------------------------------------------------------------------------
10. THINGS THAT WILL BREAK IF YOU'RE NOT CAREFUL
--------------------------------------------------------------------------------

  - Entry ids must be unique. e9, e10 and e15 are retired. New ones start at e18.
  - data-target="eN" on a card must match a real entry id.
  - The photo strip's seven cards are listed twice. Keep both halves identical.
  - Adding/removing an entry means updating the group's count in TWO places:
    the <span class="group-count"> and the category card's data-n.
  - The entry summary and the first paragraph must agree (see section 3).
  - Never put a phone number, home address or date of birth in this repo.
    It is public and it gets scraped. Email and LinkedIn only.
